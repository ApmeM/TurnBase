# Rules

## Краткое описание

Папка содержит игровую механику KaNoBu: правила расстановки фигур, создание поля, проверка допустимости ходов, разрешение боёв, обработка победителей и вспомогательная логика запоминания состояния карты. Это центральный слой, который объединяет модели, фигуры и AI-игроков.

## Какого типа классы и файлы она должна содержать

Эта папка должна содержать:
- класс `KaNoBuRules`, реализующий `IGameRules<...>`;
- словари правил побед/поражений (`Winner`, `Looser`);
- логику генерации игрового поля и начальных расстановок;
- логику проверки допустимости ходов и применения хода к полю;
- логику определения победителя и окончания игры;
- вспомогательные классы для памяти/запоминания видимого состояния поля (
  `KaNoBuFieldMemorization`);
- любые служебные компоненты, связанные с поведенческой логикой игры.

Эта папка не должна содержать чистые DTO-модели и не должна быть местом для игровой визуализации.

## Роль и устройство

`Rules` — самый важный слой проекта KaNoBu. Он задаёт правила, по которым игровая сессия развивается.

Основные обязанности `KaNoBuRules`:
- рассчитывать размер игрового поля и позиционирование игроков;
- генерировать начальный набор доступных фигур по номеру игрока;
- проверять корректность ответов на инициализацию;
- размещать фигуры в основной матрице поля;
- определять максимальное и минимальное число игроков;
- валидировать ход общими проверками поля и применять ход, запрашивая у фигуры её правила движения и возможности;
- вычислять результат боёв между фигурами;
- обрабатывать `BattleResult.FlagCaptured`: передавать все фигуры проигравшего игрока под контроль победителя независимо от типа фигуры, с которой произошло столкновение; также обрабатывать продвижение победителя до `ShipUniversal`;
- после уведомления об окончании раунда определять проигравших, отмечать их в `LostPlayers` и автоматически пропускать их последующие ходы;
- определять момент окончания игры по указанным условиям;
- определять победителей по независимому `VictoryCondition`: проигравший или отключённый игрок всё ещё может победить по пользовательскому условию (например, за удержание территории).

### Граница ответственности для правил кораблей

`KaNoBuRules` не должен содержать ветвления по конкретному `FigureType` (`if`/`switch` для `ShipScout`, `ShipMine` и т. п.), чтобы реализовать поведение отдельного корабля. Специфичные правила движения и боя задаются в `KaNoBuFigure` и классах конкретных кораблей. Для проверки хода `KaNoBuRules` передаёт фигуре сам шаг и `mainField` через `IsMoveValid`; например, скаут сам проверяет промежуточную клетку своего дальнего хода. В `Rules` остаются общие проверки границ, стен, владельца и цели хода, а также применение результата, возвращённого фигурой. Это правило касается поведения отдельных типов кораблей; общие игровые правила, такие как состав флота и повышение после побед, остаются в `KaNoBuRules`.

Правила, специфичные для отдельной фигуры, реализуются через `KaNoBuFigure.IsMoveValid`, свойства-возможности и `KaNoBuFigure.ResolveBattle`. Общая логика игрового цикла и применение результатов остаются в `KaNoBuRules`. Дополнительные словари могут использоваться для общих таблиц правил:
- `Winner` — какая фигура побеждает в бою;
- `Looser` — какая фигура проигрывает при столкновении.

`KaNoBuFieldMemorization` отвечает за отслеживание карты так, чтобы AI-игрок видел лишь то, что он должен видеть, и мог обновлять свои знания после каждого хода. Она хранит частично известную карту и синхронизирует состояние после уведомлений о ходах.

Общие правила игрового процесса вносятся в `KaNoBuRules`, а поведение конкретного корабля — в `Figures`; решения AI не должны подменять правила игры. При добавлении нового типа фигуры или изменении её механик изменения нужно согласовать с `Figures`, `Rules`, `Models`, `Players` и тестами. Это сохраняет единый источник истины для игрового состояния и не допускает разрастания проверок конкретных типов кораблей в `KaNoBuRules`.
