# Models

## Краткое описание

Папка содержит модели данных для обмена между игроками, правилами игры и игровым движком. Это DTO/контрактные классы, используемые в инициализации партии, ходе игрока и уведомлениях о событиях хода.

## Какого типа классы и файлы она должна содержать

Эта папка должна содержать:
- модели инициализации игры (`InitModel` / `InitResponseModel`);
- модели хода (`MoveModel` / `MoveResponseModel`);
- модели уведомлений после вычисления хода (`MoveNotificationModel`);
- вложенные структуры данных для передачи точек, боёв и результатов боя;
- простые переносимые объекты без бизнес-логики, за исключением удобных сериализационных/строковых методов.

Эти типы должны быть чистыми данным и описывать входы/выходы протокола игры.

## Роль и устройство

Папка `Models` представляет собой слой транспортных данных для KaNoBu. Она не содержит игровой логики и не должна содержать правила боя, стратегию игроков или состояние поля. Все типы здесь служат контрактом для движка и внешних игроков; поэтому изменение публичных полей модели нужно согласовывать с `Rules`, `Players`, `TurnBase` и сериализацией.

Основные модели:
- `KaNoBuInitModel` — параметры начальной настройки партии: размер поля, список доступных фигур, лимит ходов за ход.
- `KaNoBuInitResponseModel` — ответ на инициализацию, содержащий поле, созданное для конкретного игрока.
- `KaNoBuMoveModel` — модель хода, содержащая текущую копию поля для игрока.
- `KaNoBuMoveResponseModel` — ответ игрока, включающий список ходов `MoveStep`.
- `KaNoBuMoveNotificationModel` — результат применения хода: список уведомлений о перемещениях и боях.

Внутри `KaNoBuMoveNotificationModel` есть:
- `MoveNotification` — кортеж с `From`, `To` и необязательным `Battle`;
- `Battle` — информация о результате столкновения;
- `BattleResult` — перечисление: `Draw`, `AttackerWon`, `DefenderWon`.

Эти типы используются в движке KaNoBu в связке с `IGameRules`, `IPlayer` и `Field2D`.

Если меняется протокол игры, например добавляется новый параметр в инициализации, новый тип события боя или другой формат `MoveStep`, модель нужно обновить вместе с потребителями контракта. Специфичное поведение фигур остаётся в `Figures`, общая проверка и применение ходов — в `Rules`, а стратегия выбора хода — в `Players`.
