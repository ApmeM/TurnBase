# Players

## Краткое описание

Папка содержит реализации искусственных игроков для KaNoBu. Здесь находятся готовые стратегии, которые принимают состояние поля и возвращают список допустимых ходов. Это AI-контроллеры, реализующие интерфейс `IPlayer` и работающие поверх протокола KaNoBu.

## Какого типа классы и файлы она должна содержать

Эта папка должна содержать:
- классы игроков, реализующих `IPlayer<...>` для KaNoBu;
- стратегии инициализации поля;
- логические методы генерации ходов;
- вспомогательные методы оценки состояния поля и выбора цели;
- состояние памяти/знания о поле, если стратегия использует скрытую или частичную информацию.

Эта папка должна содержать только игровой AI и связанные с ним алгоритмы, но не правила игры и не модели данных.

## Роль и устройство

Папка `Players` содержит конкретные реализации игроков KaNoBu. Все они должны соблюдать общий интерфейс `IPlayer<KaNoBuInitModel, KaNoBuInitResponseModel, KaNoBuMoveModel, KaNoBuMoveResponseModel, KaNoBuMoveNotificationModel>`, предоставляемый ядром библиотеки `TurnBase`. Игрок выбирает действия, но не является владельцем правил их применения.

Существующие реализации:
- `KaNoBuPlayerEasy` — простой AI, который случайно выбирает допустимые ходы из доступных фигур.
- `KaNoBuPlayerMedium` — более продвинутая стратегия, которая оценивает возможные ходы по рангу полезности и запоминает состояние поля.

Логика игрока включает:
- генерацию начального поля по списку доступных фигур;
- поиск доступных ходов из текущего состояния поля;
- проверку возможности ходов и ограничений по количеству ходов в раунд;
- реакцию на уведомления о ходах других игроков;
- поддержание состояние памяти (`KaNoBuFieldMemorization`) для частично видимого поля.

Важно понимать, что AI-игроки зависят от следующих компонентов:
- `KaNoBuFigure` и типы фигур; 
- `KaNoBuRules` для логики минимума/максимума игроков, состава флота, продвижения фигур и применения результатов боя; исходы боя и ограничения движения конкретных кораблей задаются в `KaNoBuFigure` и классах фигур;
- `KaNoBuMoveResponseModel` и `KaNoBuMoveNotificationModel` для формата обмена;
- `Field2D` для навигации по карте и проверки границ.

Новые AI-игроки не должны дублировать основные правила или преобразования состояния. Они используют стандартные модели и должны учитывать ограничения `KaNoBuRules`; проверка и применение хода остаются ответственностью правил игры.
